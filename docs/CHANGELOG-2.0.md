## 一、概览

本次更新将官网从旧版整体重写为 **React 19 + Vite 8** 前端与 **Node.js/Express + SQLite** 后端的现代化架构，并在此之上完成了贡献点经济体系、Minecraft 皮肤系统、玩家任务系统、经济学看板等核心功能，历经大量修复与样式迭代，最终形成当前线上版本。

核心能力一览：

- 贡献点经济体系（申报 / 互转 / 任务 / 审计日志 / 数据看板）
- Minecraft 皮肤系统（上传 / 随机池 / 右下角常驻模型 / 档案页展示 / 头顶玩家名）
- 玩家任务系统（发布悬赏 / 接取 / 验证码核实 / 自动转账）
- 经济学看板 /economics（贡献点试点方案六项观测指标实时计算）
- PWA 支持、Tiptap 富文本、七牛云图片存储、全站浏览量统计

### 4.1 贡献点流通链路

- 获得渠道：签到/补签（固定 2 点）、完成任务、申报审核通过、管理员调整、玩家任务完成、他人转账。
- 消费渠道：商城兑换（purchase 流水）、称号购买、补签卡购买、玩家任务悬赏发布。
- 互转：`/api/contributions/transfer`，单次与单日转出上限 1000 点，双向流水 + 站内通知。
- 审计日志：所有贡献点变动经 `addContributionLog` 统一写入 `contribution_logs`（含变动前后余额 balance_after）。
- 管理端：数据看板（近 7 天流动、贡献点排行）、手动调整余额（super admin）、全量流水查询。

### 4.2 奖励规则调整（08-08 生效）

- 签到：由按连续天数递增（5~20000 点）改为 **固定 2 点**，`checkin_rewards` 表全部档位同步为 2，补签同规则。
- 发帖：+5 点 → **+2 点**。
- 评论：原 +1 点 **取消**。
- 相关前端文案（签到页、首页轮播副标题）同步更新。

## 六、个人档案页（Profile）布局迭代

档案页皮肤模型区历经十余轮布局微调，最终方案：

| 阶段 | 提交 | 说明 |
|---|---|---|
| 初始 | 2538bdc | 模型 div 高度减半（165×110 / zoom 0.64） |
| 独立浮层 | 925a68a | 模型渲染区独立为绝对定位浮层（脱离内容容器） |
| 缩放调整 | ae57d03 / b9b0c2a | div 高度 4/5、渲染区 1.5 倍、zoom 自适应（zoom='auto'） |
| 响应式 | 1e9bc0e / 63c9e75 | canvas 上移；头像区恢复骑跨分界线（marginTop -48） |
| 封面重构 | 2d40572 | 封面加高（240/180px）由 CSS 控制、底部渐变亮暗适配、模型浮层 CSS 类响应式定位、头像区提升层级、操作按钮移入昵称下方 |
| 最终微调 | 21c747b | 模型 248×165 放大 1.5 倍上移，移动端下移/右移还原 |

最终布局要点：

- 封面：桌面 240px / 移动端 180px，由 CSS `.profile-cover` 控制；底部渐变（亮色 rgba(255,255,255) / 暗色 rgba(0,0,0) 适配）。
- 模型浮层：`.profile-skin-float`（桌面 248×165 / 移动端 165×110），独立于封面之上。
- 内容容器 `position: relative; z-index: 1` 防止被封面遮挡。
- 操作按钮（管理后台/编辑资料/关注）移入昵称下方，为模型浮层让位。

| 提交 | 说明 |
|---|---|
| aeb495a | 功能：新增 /economics 经济看板，实时计算贡献点试点方案观测指标，纯只读不修改数据库 |

依据《玄剑贡献点试点方案》实现六项观测指标实时计算：

| 指标 | 口径 | 健康阈值 |
|---|---|---|
| 参与率 | 完成≥1 次任务成员数 / 近 30 天活跃成员数 | ≥50%（警戒 <30%） |
| 消费率 | 累计商城消费 / 累计获得（流水口径） | ≥40%（警戒 <20%） |
| 流通速度 | 近 14 天消费 / 平均流通存量（期初存量由流水反推） | 1–3 次/周期（警戒 <0.5） |
| 总量增速 | 近 14 天新增 / 期初存量 | ≤30%（超限关注） |
| 基尼系数 | 按当前持有量计算洛伦兹曲线面积比 | 0.3–0.5（警戒 >0.6） |
| 价格稳定 | 兑换项价格基准（黑市人工监测） | 无变动 |

页面包含：核心指标卡片（健康/关注/警戒状态灯）、总量概览、近 7 天流入流出柱状图、产量超限预警（单日≤50 / 单月≤1500）、贡献点持有 Top10、兑换项目价格一览、生态活跃数据。

**关键实现约束**：全程只读，不修改任何数据库结构与数据；部署前已备份数据库。

## 十三、数据与部署要点

- 数据库：SQLite（WAL 模式），`data/guild.db`；线上库以 8-07 线上备份为准，本地同步补齐迁移（game_id、skin_path、player_tasks）。
- 部署流程：本地构建 → git 提交推送（全中文规范提交信息）→ scp 后端文件 → 服务器执行迁移/备份 → PM2 重启（xuanjian-guild，端口 3000）→ 打包替换 frontend/dist（旧版备份 dist.bak）→ 线上验证。
- 安全规范：每次数据库变更前备份（如 guild.db.bak-economics-*、guild.db.bak-openid-*）。
